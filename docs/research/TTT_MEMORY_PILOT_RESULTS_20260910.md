# TTT Memory 首轮训练与验证（2026-09-10）

## 结论

接入、训练及推理链路可运行，但本轮没有观察到正常 TTT 相对 TempRMOT 基线的主要指标提升。不能据此宣称方法有效，也不能据此断言长期记忆无效。

本轮是小规模训练、完整视频推理的内部诊断，不是全数据集复现或正式论文结果。未根据评测结果临时调整参数。

## 实现范围

- 在完整 STReasoner 之后增强 `output_embedding`，继续执行原有后续流程；不绕过 frame_summarization、生命周期和 QIM。
- 冻结全部 TempRMOT 基线参数，仅训练新增 TTT 参数。没有修改原来的生命周期、输出过滤或 QIM 算法。
- 每个有效 Track ID 独立维护两层 MLP 的快速权重：256 → 512 → 256，GELU 激活。先通过 key/value 重建误差更新快速权重，再用 query 读取，以残差增强当前特征。
- 使用稀疏 ID 字典，避免为 300 个空检测查询提前分配完整快速模型。单轨迹快速状态约 1.003 MiB（FP32）；共享可训练参数 460,545 个。
- 当前试验以 object score > 0.5 且数值有限作为写入条件。这是固定试验设置，不是训练得到的最优可靠性阈值。
- 新轨迹首次写入不添加历史残差；独立片段和视频表达式之间重置状态，删除轨迹时清理其状态。
- 每段完整展开 10 帧计算图，段间重置。尚未实现跨片段传状态的 TBPTT。

代码和运行方式见 [实现说明](TTT_MEMORY_IMPLEMENTATION.md)。

## 为什么不能说“记忆没有用上”

正常 TTT 实际发生 4,359 次写入、5,228 次历史读取。平均特征相对残差约 0.046%，即增强向量相对原特征的扰动非常小。

与基线相比，1,907 行输出中的 1,654 行文本数值发生变化，但所有帧号与 Track ID 配对相同；输出框坐标/宽高的最大绝对变化仅约 0.012 像素。说明模块确实参与计算，但这轮训练后对最终结果的影响很弱。

可能因素包括残差幅度偏小、冻结下游对微小特征变化不敏感，以及 10 帧训练下的跨帧监督不够强。当前证据不能单独确定哪个是主因，更不能直接得出“增大 gate 就会提升”的结论。

每组推理管线累计耗时：基线 305.33 秒、正常 TTT 324.38 秒、重置组 326.08 秒。正常 TTT 本次约慢 6.2%；含数据读取和结果写入，未重复测量，不是严格模型速度基准。
