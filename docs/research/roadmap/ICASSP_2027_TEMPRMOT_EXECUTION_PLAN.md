## 0. 执行结论

### 0.1 推荐研究题目

推荐标题：

> Reliability-Guided Budgeted Query Memory for Referring Multi-Object Tracking

备选标题：

> Less but Reliable: Selective Historical Query Memory for Efficient Referring Multi-Object Tracking

推荐使用第一个标题。原因是TempRMOT的历史长度本身可能只有4—8帧，时序模块未必占据足够大的端到端计算比例。如果实测加速有限，以“高效”为唯一主张会失败；“抑制低质量历史、改善遮挡后的关联可靠性”更符合现有代码机制，也更容易形成可验证故事。

### 0.2 一句话研究问题

TempRMOT使用FIFO方式保存最近的历史Track Query，但遮挡、低置信度检测和错误关联产生的历史状态可能污染后续时序推理；能否在固定甚至更小的记忆预算下，只保留可靠且互补的历史Query，从而改善遮挡场景中的关联质量，并减少时序推理成本？

### 0.3 核心假设

- H1：最近的历史Query不一定是最可靠的历史Query。
- H2：遮挡或低置信度帧产生的Query进入FIFO记忆后，会持续影响随后数帧的分类、Refer判断和框回归。
- H3：可靠性与特征互补性联合选择，比FIFO、均匀采样、置信度单独选择更有效。
- H4：固定预算选择可以在不降低HOTA/AssA的情况下缩小有效历史长度；但端到端FPS是否明显提高必须通过剖析确认，不能预设。

### 0.4 论文最小贡献

只有同时形成以下三项，才构成可投稿的ICASSP论文：

1. 对TempRMOT历史Query污染现象的可重复诊断；
2. 一个轻量、可解释的可靠性—多样性历史选择策略；
3. 在固定公平条件下同时报告跟踪精度、遮挡鲁棒性和计算代价。

### 0.5 当前现实起点

截至2026-07-21，本地状态为：

- Python、PyTorch、CUDA和MSDA扩展已通过；
- RoBERTa与官方TempRMOT checkpoint已离线验收；
- Refer-KITTI-V2数据完整性错误数为0；
- 推理和TrackEval兼容性补丁已经完成；

## 2. 方法设计

## 2.1 首先确认真正生效的历史路径

当前仓库中存在两套容易混淆的历史机制：

1. `models/spatial_temporal_reason.py`中的`hist_embeds`和`hist_padding_masks`；
2. `models/memory_bank.py`中的`mem_bank`、保存阈值和时序注意力。

官方V2配置未必同时启用两套机制。因此在修改代码前必须通过运行时Hook和配置记录回答：

- 官方checkpoint实际使用哪一条历史路径？
- `hist_len`的实际值是多少？
- `memory_bank_len`与MemoryBank是否真正参与前向？
- STReasoner每帧被调用几次？
- 哪些字段在训练和推理时被更新？

如果只有`SpatialTemporalReasoner.frame_shift()`中的FIFO历史生效，第一版方法只修改该路径。不得为了扩大方法而同时重写未启用的MemoryBank。

## 2.2 现有FIFO机制

当前`frame_shift()`将最旧历史丢弃，并把当前`output_embedding`追加到队尾：

```text
history_next = history_current[1:] + current_query
```

这个更新只考虑时间新近性，不考虑：

- 当前Query是否来自低置信度帧；
- 目标是否处于严重遮挡；
- Refer分支是否认为该Query与语言不匹配；
- 当前Query是否与已有记忆高度重复；
- 当前帧是否发生了可能的错误关联。

## 2.3 提议方法：Reliability-Guided Budgeted Query Memory

对每个候选历史Query计算轻量效用分数：

```text
utility =
    w_det     × detection_confidence
  + w_ref     × referring_confidence
  + w_novelty × feature_novelty
  + w_recent  × recency
  - w_risk    × association_risk
```

其中：

- `detection_confidence`：当前目标分类/检测置信度；
- `referring_confidence`：当前Query满足语言描述的置信度；
- `feature_novelty`：该Query与已保存Query不重复的程度；
- `recency`：避免记忆全部由过旧状态组成；
- `association_risk`：低IoU、轨迹丢失状态、置信度骤降或明显框跳变形成的风险指标。

初始实现不引入新的大网络，采用归一化指标和少量可验证权重。只有规则版本有效后，才尝试两层MLP学习权重。

### 记忆更新规则

固定容量为B：

```text
candidate_memory = old_memory + current_query
selected_memory  = select_top_B(candidate_memory, utility, diversity_constraint)
```

为防止退化，选择时至少保留：

- 一个最近且有效的Query；
- 一个历史最高可靠性Query；
- 其余位置依据可靠性与特征互补性选择。

### 聚合规则

MVP继续使用TempRMOT原始时序Transformer，只改变输入的历史集合与padding mask，以隔离“选择策略”的贡献。

可选增强是在聚合时加入效用权重：

```text
attention_bias[j] = scale × normalized_utility[j]
```

该增强只有在选择策略已经有效、且时间允许时才实现。

## 2.4 实现层级

### M0：诊断版

- 不训练；
- 导出每帧历史Query、置信度、Refer分数、框、目标ID和padding mask；
- 对遮挡前、遮挡中和恢复后的状态做可视化；
- 验证低质量历史是否与后续错误相关。

### M1：规则选择MVP

- 固定模型权重；
- 将FIFO替换为可靠性—多样性选择；
- 只改历史更新，不改时序Transformer；
- 在固定小规模validation subset上快速比较。

### M2：可学习轻量选择

- 冻结Backbone、文本编码器、检测头和原TempRMOT主体；
- 只训练小型评分器或可学习权重；
- 参数增量目标小于0.5M；
- 如果M1已经达到强结果，M2不是必需项。

### M3：可靠性加权聚合（可选）

- 只在M2于2026-08-20前稳定后尝试；
- 如果两天内无稳定收益，立即删除；
- 不允许把M3变成另一个复杂Transformer。

## 3. 数据与实验协议

## 3.1 数据使用原则

主数据集使用已经验收的Refer-KITTI-V2：

- 17个训练视频；
- 4个测试视频；
- 测试表达式共862条；
- 官方图像、标签和表达文件保持不修改。

禁止在官方测试集上反复调权重。必须从17个训练视频中建立固定、视频不重叠的validation split。

## 3.2 建议的数据划分

第一周根据每个训练视频的表达式数量、目标数量、轨迹长度和遮挡比例生成统计表。随后固定：

- Train：14个视频；
- Validation：3个视频；
- Test：官方4个测试视频。

Validation视频选择应覆盖：

- 至少一个高遮挡视频；
- 至少一个长轨迹视频；
- 至少一个目标密集视频。

划分完成后输出：

- `train_videos.txt`；
- `val_videos.txt`；
- 每个文件的SHA-256；
- 划分统计表；
- 固定随机种子。

测试集只允许在方法和超参数冻结后运行完整评测。若因程序错误必须重跑，需要在实验日志中记录原因。

## 3.3 三级实验规模

### Smoke subset

- 1个视频；
- 5—10个表达式；
- 作用：验证程序不崩溃、输出格式正确、速度测量可用；
- 不用于方法选择。

### Pilot validation subset

- 从固定validation视频选择约50—100个表达式；
- 必须包含短遮挡、长遮挡、无明显遮挡三组；
- 作用：快速筛选方法与权重；
- 所有版本使用完全相同的表达式清单。

### Full evaluation

- 完整validation；
- 冻结后运行官方862条测试表达式；
- 作用：形成最终主表。

## 3.5 核心指标

### 跟踪质量

- HOTA；
- DetA；
- AssA；
- IDF1；
- ID Switch；
- 原TempRMOT评测脚本中的Refer相关指标。

### 可靠性分组

- 无遮挡；
- 短遮挡；
- 长遮挡；
- 遮挡恢复后1—5帧；
- 低置信度区间；
- 长轨迹与短轨迹。

如果数据没有显式遮挡标签，可依据GT框暂时消失、可见性字段或轨迹连续性定义代理分组，但必须在论文中明确其局限，不能称为真实遮挡标注。

### 效率

- 端到端FPS；
- 每帧延迟中位数和P95；
- 时序模块单独延迟；
- 峰值GPU显存；
- 有效历史Query数量；
- 新增参数量；
- 理论时序注意力计算量。

### 统计稳定性

- 至少3次独立计时；
- 计时前预热；
- CUDA计时前后同步；
- 按视频或表达式bootstrap得到95%置信区间；
- 不用单次运行的微小差异作为主要结论。

## 3.6 效率测量协议

1. 固定batch size为1；
2. 使用同一GPU且记录型号、驱动、CUDA和PyTorch；
3. 关闭可视化、日志图像保存和非必要I/O；
4. 预热至少30帧；
5. 对同一表达式运行3次，报告中位数；
6. 使用CUDA Event测量GPU模块时间；
7. 使用墙钟时间测量端到端时间；
8. 分别报告模型计算和数据读取时间；
9. 显存使用`max_memory_allocated`并在每次运行前清零；
10. 如果时序模块低于端到端时间的10%，不得宣称“显著实时加速”，只能报告局部计算或记忆减少。

## 4.2 Gate 1：现象成立

截止：2026-08-02

至少满足以下两项：

- 历史长度或历史质量对AssA/HOTA存在稳定影响；
- 遮挡/低置信度历史与恢复后的错误关联显著相关；
- FIFO明显保留了重复或低可靠性Query；
- Oracle历史选择相对FIFO存在有意义上限；
- 时序模块的计算或记忆占用达到可优化程度。

失败处置：不实现复杂选择器。若没有历史污染现象，也没有效率瓶颈，终止该论文方向。

## 4.3 Gate 2：MVP有效

截止：2026-08-09

在固定pilot validation subset上，Ours-M1需要满足以下之一：

- AssA提高至少0.7点且HOTA不下降；
- HOTA提高至少0.5点；
- 使用一半历史预算时，HOTA下降不超过0.3点且时序模块延迟降低至少25%；
- 长遮挡组的ID Switch下降至少10%，整体HOTA不明显下降。

以上阈值是继续投入门槛，不是论文最终结果承诺。

失败处置：只允许一次有依据的公式/权重修订。2026-08-12仍无效则终止，不进入可学习M2。

## 4.4 Gate 3：论文级结果

截止：2026-08-31

建议达到：

- 完整validation上至少一个主要跟踪指标稳定提高；
- 改善集中在有理论动机的遮挡/低置信度组；
- 相比置信度单独选择和新颖性单独选择仍有增益；
- 参数增量和延迟增量可忽略，或历史预算明显下降；
- 至少两个随机种子/重复运行趋势一致；

## 9. 资源预算

### 最低条件

- 1张24GB以上GPU；
- 稳定的Refer-KITTI-V2本地数据；
- 官方checkpoint；
- 约150GB新增实验存储；
- 每天至少6小时连续研究时间；
- 至少一位合作者在9月12日前完成内部审稿。

### GPU预算策略

在阶段B完成前不承诺总GPU小时，因为一次862表达式评测的真实耗时尚未测定。完成单Query与50表达式pilot后，按下式估算：

```text
estimated_full_eval_time =
    pilot_wall_time / pilot_query_count × 862 × safety_factor

safety_factor = 1.2 to 1.5
```

实验优先级：

1. baseline闭环；
2. 现象诊断；
3. M1与必要baseline；
4. 完整validation；
5. 消融；
6. M2；
7. M3可选增强。

如果算力不足，首先删除M3和大规模超参数搜索，不得删除公平baseline和主消融。

## 12. 可行性与采纳判断

### 故事完整性：当前7.5/10

问题—诊断—选择方法—遮挡实验—效率分析可以形成闭环。当前扣分来自核心现象尚未通过实验验证。

### 技术可行性：8/10

本地环境、模型权重和数据已经基本就绪，方法主要改动历史更新路径，不需要训练新的大模型。最大技术风险是阶段H尚未关闭，以及官方checkpoint的真实历史配置可能使效率空间很小。

### 创新性：6.5/10

可靠性记忆选择不是全新概念；创新必须来自RMOT中特有的Refer置信度、遮挡后身份关联和严格历史污染诊断。若最终只是confidence Top-K，创新性可能降至4/10。

### ICASSP匹配度：8/10

问题适合Image/Video Processing、Multimedia Signal Processing和Computer Vision方向；4页篇幅也适合单一轻量模块与扎实实验。

### 录用可能性

在尚无实验结果时不能给出可靠录用概率。按结果形态判断：

- 只有复现和历史长度曲线：低；
- confidence Top-K带来轻微单点提升：偏低；
- 有历史污染诊断、完整baseline、遮挡组明显改善、总体指标不退化：有竞争力；
- 同时实现稳定AssA/HOTA改善与明确预算收益：较强投稿形态。

### 95%执行置信度的含义

本计划可对“在截止前得到明确Go/No-Go科研结论”给出约95%的条件置信度，前提是：

- 阶段H在2026-07-26前通过，最晚不超过7月29日；
- 至少一张24GB GPU稳定可用；
- 每天按计划投入时间；
- 严格执行Gate，不因结果不好不断添加模块；
- 官方投稿时间、模板或政策若更新，立即同步。

这不等于95%的录用概率，也不等于方法一定产生正增益。
